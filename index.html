Day 1 · 11/03(화) — Slack 기초

오늘 목표 — Slack을 「메신저」가 아니라 사람과 프로그램이 같이 일하는 곳으로 씁니다. 오늘 끝나면 프로그램이 내 채널에 글을 올립니다.

오늘 쓰는 안내 — 게시용 앱 · Webhook · Block Kit 안내 (화면 캡처 18장 · Windows/Mac 명령)

M1. 오프닝 · 3일 지도 · 09:30

  • 목표 — 3일이 파이프라인 4칸을 뒤에서부터 쌓는다는 것을 압니다
  • 할 일 — 워크스페이스 이름 클릭 → 「Pro 체험판」인지 확인. 무료로 보이면 이 자리에서 체험판을 시작합니다. 카드 입력 화면이 나오면 멈추고 손을 듭니다. 체험판 종료일을 메모합니다

M2. Slack의 구조 — 채널 · 스레드 · 멘션 · 10:00

  • 핵심 — Slack은 방이 사람이 아니라 주제 기준입니다. DM은 채널 밖이라 DM에서 내린 결정은 다른 사람도, AI도 못 찾습니다
    • 한 주제는 한 스레드 · 채널 본문에는 새 주제만
    • 멘션의 세기 @이름 < @here < @channel — @channel 은 아껴 씁니다
    • 「확인했습니다」 답장 대신 이모지 👀 → 🔄 → ✅
  • 실습 (40분, 짝)
    1. 짝을 내 워크스페이스에 초대 (워크스페이스 이름 → 사람 초대 → 이메일)
    2. 상대 #general 에 질문 1개 → 상대는 스레드로 답 → 「채널에도 보내기」 차이 확인
    3. 이모지로 상태 3단계 표시
    4. 「이번 주 할 일」을 굵은 제목 + 체크 목록 + 링크 1개로
    5. 프로필 → 시간대 서울 확인
  • 흔한 실수 — 회사 Slack 창에서 실습 → 왼쪽 위 이름이 STA3-<이름> 인지 먼저 봅니다

M3. 채널 설계 · 11:00

  • 핵심 — 채널 이름은 접두어로 성격을 말합니다 · 공개가 기본(비공개는 검색도, AI도 못 읽습니다) · 캔버스 = 채널의 문서, 리스트 = 채널의 할 일

    접두어 용도 이번 수업
    prj- 프로젝트 #prj-주간리포트
    data- 데이터 질문·요청 #data-질문
    alert- 자동 알림 — 기계가 쓴다 #alert-<내주제>
    test- 실험 — 망가져도 된다 #test-<이름>

  • 실습 (40분)

    1. 채널 4개 만들기 — 설명 한 문장씩
    2. #prj-주간리포트 → 채널 캔버스: 목적 / 대상 / 일정 11/03~06 / 내 Tableau 사이트 링크
    3. 같은 채널에 리스트 「미니프로젝트 할 일」 5개 — 담당·기한·상태 열
    4. #data-질문 에 양식 메시지 고정 — [요청] 지표: / 기간: / 기한: / 설명:
    5. 옆 사람 채널 목록만 보고 각 채널의 용도를 맞혀 봅니다
  • 산출물 — 채널 4개 · 캔버스 · 리스트 · 고정 양식 (체험판이 끝나도 캔버스·리스트는 남습니다)

M4. 찾기 · 정리 · 알림 · 12:00

  • 핵심 — 검색 한정어 in:#채널 · from:@사람 · has:link · after: · before: 를 하나씩 붙여 가며 좁힙니다. 한정어와 값 사이는 띄우지 않습니다(from: @이름 ✕)
  • 실습 (20분) — 짝 워크스페이스에서 「오전에 짝이 올린 링크」를 한정어 2개 이상으로 찾기 · #alert- 채널 알림을 「멘션만」으로 · 퇴근 후 방해 금지 예약

M5. 코드 없는 자동화 · 13:30

  • 핵심 — 워크플로 = 트리거 + 단계. 내일 만들 4칸과 같은 모양입니다. 조건 분기·외부 데이터 조회·계산은 안 됩니다 — 여기서 막히는 것만 Claude Code로 넘깁니다
  • 실습 1 (35분) — 「데이터 요청 접수」 워크플로 · 따라 하기 영상 Slack 워크플로 빌더로 코드 없이 자동화 만들기 (3:44)
    1. #data-질문 채널 ⋮ → 워크플로 추가 → 처음부터 새로 만들기 → 트리거 「Slack의 링크에서」
    2. 단계 ① 양식 — 요청자(사람) · 지표 · 기간 · 기한(날짜) · 설명, 필수 체크 (질문을 추가하면 앞 질문의 「필수」가 따라옵니다 — 설명은 풀어 줍니다)
    3. 단계 ② 양식 응답을 #data-질문 에 메시지로 게시 (응답 값은 자동으로 채워집니다. 빠지면 「변수 삽입」)
    4. 단계 ③ 나에게 DM
    5. 게시 → 짝이 내 워크스페이스에서 한 번 접수해 봅니다
  • 실습 2 (15분) — 때가 되면 알리기 · 따라 하기 영상 Slack /remind · 예약 전송 (1:20)
    1. /remind #alert-<내주제> "주간 지표 확인" every Monday at 9am → /remind list (Slackbot이 「나에게만 표시」로 답합니다)
    2. 보내기 ▾ → 「내일 오전 9:00」 → #prj-주간리포트 에 「Day 2 시작」 예약 전송 (확인·취소는 입력창 위 「모든 예약 메시지 보기」)
    3. 나에게 리마인드 「Slack·Tableau 체험판 종료일 확인」 → 왼쪽 「해야 할 일」에 들어갑니다
  • 기억할 것 — 워크플로는 체험판이 끝나면 멈춥니다. 그래서 매주 도는 리포트는 Webhook으로 만듭니다
  • 막히면 — 「워크플로 추가」가 안 보임 → Pro 체험판이 아닙니다 · 조건 분기·반복에 BUSINESS+ 표시 → 오늘은 쓰지 않습니다

M6. Slack AI · Slackbot · 14:30

  • 핵심 — AI 요약은 채널에 쌓인 것보다 좋아질 수 없습니다. DM에서 오간 결정, 본문에 흩어진 답장은 AI가 연결하지 못합니다
  • 실습 (5분) — 내 채널에서 채널 요약 · 스레드 요약을 눌러 봅니다. 안 보이면 짝 화면으로 (체험판이 끝나면 사라지는 기능이라 과제에는 쓰지 않습니다)

M7. 게시용 앱 + Incoming Webhook ★ · 15:00

  • 핵심 — 앱 = 워크스페이스에 들어온 「프로그램 사용자」, Webhook = 그 앱이 채널 1개에 글을 넣는 주소. Webhook 주소는 비밀번호입니다 — 작업 폴더의 .env 에만 적습니다. 체험판이 끝나도 계속 됩니다
  • 안내 — 게시용 앱 · Webhook · Block Kit 안내 1절 · 따라 하기 영상 Slack Incoming Webhook 만들고 PowerShell로 첫 메시지 보내기 (3:19)
  • 실습 (70분)
    1. api.slack.com/apps → Create New App → Blank app → 이름 Weekly Report(한글은 에러) → 내 워크스페이스
    2. Incoming Webhooks 켜기 → #test-<이름> 용 1개 → #alert-<내주제> 용 1개
    3. .env 에 저장 — 명령을 먼저 붙여 넣고 → 멈추면 Slack에서 Copy → Enter (순서가 바뀌면 클립보드가 덮입니다)
    4. 시험 게시 — Windows Invoke-RestMethod · Mac curl
    5. #test 와 #alert 둘 다 「webhook test」가 보이면 끝
  • 흔한 실수 — 회사 워크스페이스에 앱을 만듦 · .env 가 .env.txt 로 저장됨(파일 확장명 보기 켜기)

M8. Block Kit — 읽히는 메시지 · 16:30

  • 핵심 — 3초 안에 결론이 읽혀야 리포트입니다. 맨 위 주체 + 결론 숫자, 그 아래 근거 숫자, 맨 끝 출처 · 기준일 · 집계 기간. 증가 = 파랑 🔵 · 감소 = 빨강 🔴 (매출 같은 일반 지표 기준). 멘션은 넣지 않습니다
  • 실습 (45분) — 안내 2절
    1. Block Kit Builder에서 header · section(필드 2열) · divider · context
    2. 숫자 자리는 {매출} {증감률} 같은 자리표시자로
    3. JSON을 VS Code로 작업 폴더에 slack_템플릿.json 저장
    4. 임의 숫자를 넣고 안내 2절 ④ 명령으로 #test 에 게시
    5. 옆 사람에게 3초 보여 주고 결론을 말하게 합니다
  • 막히면 — 강사 시안 JSON을 받아 slack_템플릿.json 으로 저장하고 ④만 실행합니다
